# Anyi2 CFSM-SAO 优化与验收路线

本文件记录 fork（`anyi2/CFSM-SAO`）的专属维护范围。所有改动先进入 `preview`，在线构建只发布到 `dist-preview`。不得由本路线自动修改 `main` 或正式 `dist`。

## 已落地的工程可靠性改进

- `package.json` 与 lockfile 的项目版本必须一致。
- `npm run package` 负责生成可安装 ZIP，内容只包括主题入口 `index.html` 和 `assets/`。
- `verify-build.mjs` 检查允许的构建目录结构，以及 HTML、CSS、JS 的本地资源引用。
- 在线构建 CI 增加 Playwright 桌面/移动端冒烟检查，覆盖 React 挂载、主机名详情深链接和资源 404。
- WebSocket 连续退避重试耗尽后改为 60 秒冷却重试；浏览器回到前台时提前重试。服务端以 1008 拒绝订阅仍保持停止重试，避免对确定性错误进行无意义循环。
- 尊重系统减少动态效果偏好，静态展示仍保留实时监控内容。

## 数据、实时性与身份边界

- 继续使用三态数据语义：缺失/未配置、超时、真实数值（包括 0）不得混淆。
- 新增历史字段必须保持缺失值为缺失，不能用 0 填充。
- 多站部署中的同 UUID 冲突仍需单独设计全局身份命名空间；在未确认后端身份规则前，不自动改写服务器 ID，以免破坏 WebSocket、历史 API 和旧书签。
- 告警推送需依赖持续运行的服务端任务/通知通道；纯静态主题不能在浏览器关闭后可靠执行监控，因此不能把浏览器本地提示宣传成离线告警服务。

## 功能增强的实施约束

1. 多节点对比：只能比较同一时间口径下的有效样本；缺失采样必须显式显示，不补零。避免在前端并行发起过多历史请求。
2. 异常提醒：前端可提供页面在线期间的辅助提醒；邮件、Telegram、Webhook 和页面关闭后的监控必须由服务端实现。
3. 仪表盘预设：需明确是管理员同步配置还是设备本地配置，默认不覆盖现有用户的排序、卡片和隐藏节点设置。
4. 历史导出：导出当前后端真实返回的字段、时间戳和单位；不将估算值或缺失值转成真实数据。
